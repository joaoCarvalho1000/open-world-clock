# App contract: settings, IPC bridge and DOM hooks (the tests rely on these; change code and this file together)

## Settings (owned and validated by src/main.js)
Stored in `<userData>/settings.json`; userData follows productName (`%APPDATA%\Open World Clock`). Before the first load, main copies settings.json/.bak from `%APPDATA%\World Clock` or `%APPDATA%\Free World Clock` when the new folder has neither (skipped when WC_USER_DATA is set).
The file is handled by `src/settings-store.js` (no Electron import; unit-tested in test/unit/settings-store.test.js): `createSettingsStore({ dir, defaults, validate, fs, legacyDirs, appDataDir, skipMigration })` returns `{ load(), write(settings), migrate() }`. main passes its own DEFAULTS and VALIDATE (they stay in main.js; scripts/export-shared.mjs reads DEFAULTS there). load: settings.json, else settings.json.bak when the main file is missing, corrupt or not a plain object; a leading UTF-8 byte order mark is ignored; every known key goes through its validator; `bounds` needs four integers. Unknown top-level keys are kept aside (never `__proto__`, `constructor`, `prototype`), written back unchanged on every save and never part of `settings` or publicSettings. write: temp file + fsync, the current file copied to .bak only when it parses, then rename; a rename failing with EPERM, EACCES or EBUSY (the file held by an antivirus, a sync client or an editor) is retried up to 5 times 40 ms apart, then the data is written in place and the temp removed.
Existing: zones, hour12, showSeconds, alwaysOnTop, opacity, theme, launchAtLogin, firstRun, bounds, labels, layout, language, tipSeen, hours, planner.
`opacity` (background alpha) is clamped to 0.6..1 on every write and on load (lower values let the desktop wash out the text).
First run (`firstRun` true, renderer): the saved zones become the defaults plus the local zone (first when it is not already a default), minus every default that shows the same time all year as an earlier one (`WCTime.uniqueClocks(zones, refMs)`: same UTC offset now and on Jan 15 and Jul 15 UTC; the first of each group stays, and the local zone wins its group). A São Paulo user gets São Paulo, Lisbon, New York, Los Angeles, Singapore (London has Lisbon's clock). main's DEFAULTS.zones (and shared/golden.json defaultZones) are unchanged; existing settings are never touched.
First run also picks the clock format (main, `app.whenReady`, before the window): `hour12 = prefers12h(systemLocale())` (`src/locale-prefs.js`: true when `Intl.DateTimeFormat(locale, { hour: 'numeric' })` resolves hourCycle h11 or h12; false for an empty or unknown locale or on any error). `systemLocale()` is the Windows Region format, `app.getSystemLocale()` (for example 'pt-BR' while `app.getLocale()` is 'en-US'); dev runs with `WC_SMOKE` use env `WC_SYSTEM_LOCALE` or 'en-GB' (so the suite is 24-hour on any machine), other dev runs `WC_SYSTEM_LOCALE` when set. Nothing is saved there: the renderer's first-run `setSettings({ zones, firstRun: false })` writes the whole settings object, hour12 included. DEFAULTS.hour12 stays false (golden.json and the iPhone defaults do not move); existing users are never touched. Known limit: a custom short-time format set in Windows Region settings is not read.
New in v1.1:
- `labels`: object mapping zone id -> custom label string (1..40 chars, trimmed). Empty string or missing = use city name. Validate: plain object, string keys that are valid zones, string values <= 40 chars.
- `layout`: 'strip' | 'compact' | 'vertical'. Default 'strip'.
- `language`: 'auto' | 'en' | 'pt' | 'es'. Default 'auto' (or value of env WC_LANG if set to en/pt/es).
- `tipSeen`: boolean. Default false.
- `closeHintSeen`: boolean. Default false. Set true once Windows actually showed the one-time tray notification (Tray `balloon-show`) or it was clicked, after the first close to the tray. While Focus assist or Do not disturb drops it, it stays false and the notification is tried on a later close, at most 3 times a session (listeners registered once in createTray; not in WC_SMOKE runs).

Closing: the X button (`btnClose`, preload `hide()`), Alt+F4 and the taskbar close all hide the window to the tray; the app keeps running. Quit is only in the tray menu (and OS shutdown). `btnMin` minimizes to the taskbar (preload `minimize()`, IPC `window:minimize`). There is no quit IPC (round 2: the unused preload `quit()` and `window:quit` were removed).

Added in v1.3 (planner):
- `hours`: plain object mapping zone id -> `{ start: 'HH:MM', end: 'HH:MM', days: [0..6] }` (24h times; `days` = working weekdays, 0 = Sunday). Default `{}`. A zone with no entry uses the renderer fallback 09:00 to 18:00, Mon to Fri (`days: [1,2,3,4,5]`). Validation drops invalid entries individually: key must pass isZone (and be < 64 chars); `start`/`end` must match `/^([01]\d|2[0-3]):[0-5]\d$/`; `start !== end` (`end < start` is allowed and means an overnight shift ending the next day); `days` must be an array of 1..7 unique integers 0..6. Stored days are sorted ascending; extra keys on an entry are discarded. A non-object `hours` value is rejected as a whole (existing value kept).
- `planner`: boolean. Default false. Whether the overlap planner view is open. It is NOT a layout; since v1.4 it is an overlay view with its own remembered window size (see Per-view window sizes).

Added in v1.4 (per-view window sizes):
- `viewSizes`: plain object `{ strip?, compact?, vertical?, map?, planner?, mapVertical?, plannerVertical? }`, each `{ width, height }` (integers). The `*Vertical` keys (v1.2 go-live) are the map/planner sizes while the layout is vertical (tall and narrow), so a wide strip planner size never lands in the vertical layout. Default `{}`. Main-owned: written only by main, never accepted from `settings:set` (a renderer patch containing it is ignored). Validation on load drops bad entries individually (unknown key, non-object, non-integer width/height) and clamps to >= MIN_W x MIN_H (280x120) and <= 16384; the display work area clamp happens when a size is applied. Persisted in settings.json; publicSettings() includes it (read-only for the renderer).

publicSettings() also returns read-only flags: `version`, `portable` (bool), `store` (bool, true when process.windowsStore), `shortcut` (accelerator string actually registered, or '' if registration failed), `systemLanguage` ('en' | 'pt' | 'es': the first of the Windows preferred display languages the app speaks, so pt-PT/es-419 resolve correctly; the renderer's 'auto' language and the tray use it), `systemLocale` (round 2: the Windows Region format, `app.getSystemLocale()`, for example 'en-GB'; '' in WC_SMOKE runs unless env `WC_REGION_LOCALE` is set, so the suite reads en-US dates on any machine; see Region dates).

## Preload API (window.wc)
Existing: getSettings, setSettings(patch) -> Promise<publicSettings>, onSettings(cb), hide, dragStart, dragMove(dx, dy).
- `setTrayNames(names)` (round 2): `{ zone: card name }` for the tray tooltip. Fire-and-forget (ipc `tray:names`). The renderer sends it from buildStructure when the cards are rebuilt (cities, labels, layout or language changed) and only when the names changed, never on a tick. main ignores it unless the sender is trusted, it is a plain object with at most 50 keys, every key is a valid zone (< 64 chars) and every name a non-empty string of at most 40 chars.
New:
- `copyText(data)`: writes to the system clipboard via main (electron clipboard). Returns Promise<boolean>. `data` is a string (plain text), or `{ text, rows: [[city, time, date], ...] }` (round 2, "Copy times"): main then writes the text and an HTML table it builds and escapes itself (`src/share-format.js` htmlTable: the first text line as a caption, then the rows; inline styles only) in one `clipboard.write([new ClipboardItem({ 'text/plain', 'text/html' })])`, so Outlook and Teams paste a table and the page never sends HTML. Refused (false): untrusted sender, text over 5000 characters, rows that are not a list of 1 to 50 rows of three strings of at most 200 characters.
- `saveIcs({ startMs, endMs, title, description })` (round 2): a calendar invite. main (ipc `ics:save`, trusted sender only) checks it again (`src/share-format.js` validIcsRequest: finite times, end after start and at most 7 days later, title 1 to 100 characters, description at most 2000), builds one VEVENT (buildIcs: PRODID `-//Open World Clock//EN`, UID `crypto.randomUUID()@openworldclock.com`, DTSTAMP/DTSTART/DTEND in UTC, RFC 5545 text escaping, CRLF lines folded at 75 octets; unit-tested in test/unit/share-format.test.js), shows `dialog.showSaveDialog(win, { defaultPath: <Downloads>/meeting.ics, filters: Calendar .ics })` and writes the file. Resolves 'saved', 'canceled' or false. The user picks the path, so the Store build needs no extra capability; nothing goes over the network.
- `onSettings(cb)` must return an unsubscribe function.
- `panel(open)`: settings panel opened/closed (main grows the window for it and restores it afterwards).
- `setView(view)` (v1.4): overlay view now on screen, `'map' | 'planner' | null`. The renderer calls it wherever the map or planner is toggled, BEFORE the matching `setSettings({ planner })`, so a map <-> planner switch resizes once. Fire-and-forget (ipc `window:view`); any other value is sent as null.
- `openStartupSettings()`: Microsoft Store build only. Fire-and-forget (ipc `window:startupSettings`); main opens the fixed URI `ms-settings:startupapps` (Windows Settings > Apps > Startup) when the sender is trusted and `process.windowsStore` is true, and ignores it otherwise.

## Main-process behaviors
- Layout change resizes the window to that layout's remembered size (`viewSizes[layout]`), or the first time to the default: strip 1160x250, compact 1160x150, vertical 300x640 (and updates the locked drag size). See Per-view window sizes. The compact layout never opens taller than 220 (COMPACT_MAX_H).
- All programmatic window geometry goes through `placeWindow(bounds)`: at fractional display scaling Windows lands setBounds 1 DIP up/left and 2 DIP larger (the constructor 6x5 larger); placeWindow reads back once, corrects by the difference and remembers the correction, so applied and stored sizes are exact (no growth on round trips).
- Settings are saved atomically (settings.json.tmp, then rename; the previous valid file is kept as settings.json.bak and used when settings.json is corrupt).
- Auto-update is OFF unless the build sets `build.extraMetadata.wcUpdates: true` (signed builds with a real publish config only). Default package.json sets it false.
- A crashed renderer is reloaded (`render-process-gone`, any reason but `clean-exit`); a renderer unresponsive for 10 s is crashed with `forcefullyCrashRenderer()` and render-process-gone reloads it (the hang timer calls `scheduleReload()` itself only if the crash call throws). One `scheduleReload()` with a pending-timer guard, so two reloads never overlap, and a backoff (`src/reload-guard.js` createReloadGuard({ max: 5, windowMs: 120000 }): delay `min(30000, 500 * 2^(n-1))` for the n-th crash in the last 120 s, so 500 ms, 1 s, 2 s, 4 s, 8 s; the 6th in the window returns null). On null main stops reloading, logs once and leaves the window as it is; tray Show/Hide or a second-instance launch resets the history and tries again. A page (re)load undoes the settings panel geometry and drops a stale map overlay. Windows session end flushes settings. App user model id `io.joao.worldclock`, set with `app.setAppUserModelId` except in the Store build (`process.windowsStore`): there the MSIX package gives the id (`JoaosApps.OpenWorldClock_...!WorldClock`), and a different explicit id would group the window's taskbar button apart from the Start tile and the taskbar pin. Tray tooltip: the localized product name ('Open World Clock'), then one line per card, `<name> <time>` ('Lisbon 17:37'; with `hour12`, '5:37 PM'), in card order, cut to 127 characters (whole lines only). Times use a cached Intl.DateTimeFormat per zone and clock format and are built when the pointer moves over the icon (Tray `mouse-move`, at most every 5 s), when names arrive and on refreshTray; there is no timer.
- Window position is saved at once (`captureBounds(true)`: no visibility check, no size correction, never the panel, snapped or maximized geometry, skipped while minimized) before the window hides to the tray, in before-quit and at session end (`session-end`, `query-session-end`), then settings are flushed; moves otherwise save through the 300 ms `persistBounds` debounce, which calls `captureBounds(false)`.
- Microsoft Store build: `openExternalSafe` refuses any `ko-fi.com` host (and subdomain) while `process.windowsStore`, whatever the page asks for.
- The renderer is served from the custom scheme `app://owc` (round 2): `protocol.registerSchemesAsPrivileged([{ scheme: 'app', privileges: { standard: true, secure: true } }])` at module scope, `protocol.handle('app', serveApp)` in whenReady before the window, `win.loadURL('app://owc/index.html')`. serveApp answers only host `owc` (else 404), decodes the path, resolves it under `src/renderer` (inside app.asar when packaged; a path outside it gets 403) and returns `net.fetch(pathToFileURL(file))`. CSP `'self'` is that origin. The renderer keeps no localStorage or IndexedDB, so the origin change lost nothing.
- IPC is trusted only from the window's main frame showing the app's page (frame identity + `src/url-trust.js` isAppUrl: the URL before any query or hash is exactly `app://owc/index.html`; any other host, path, dot segment, credentials, port, scheme or a file:// URL is refused). The URL no longer depends on the install folder, so folders such as an 8.3 %TEMP% (`C:\Users\JOHNSM~1\...`, where the portable build unpacks), `sq[1] pct% João` or `a%41b` behave the same.
- No global shortcut (there was one early on; it was removed). `shortcut` in publicSettings is always ''.
- Launch at login follows Windows both ways (packaged, non-Store builds). At startup and on every window `focus` (whatever `launchAtLogin` is), main looks up the Run entry named `io.joao.worldclock` (`app.getLoginItemSettings({ path }).launchItems`, for the current exe, then for `World Clock.exe` / `Free World Clock.exe` in the same folder, each path both unquoted and quoted; an entry named `electron.app.World Clock` / `electron.app.Free World Clock`, left by versions before the AppUserModelId, counts too) and applies `src/login-item.js` loginItemAction({ want: settings.launchAtLogin, item, exe }). Electron writes the exe unquoted and reads the value back as a command line, so a path with spaces comes back as `path` plus `args`; loginItemAction joins them before comparing. `'settingOff'` (setting on, but no entry, or `enabled: false` because the user turned it off in Task Manager > Startup apps) sets `launchAtLogin` false, saves and broadcasts WITHOUT touching the registry; `'settingOn'` (setting off, but an enabled entry for this exe: the user turned it back on in Task Manager or Settings > Apps > Startup) sets `launchAtLogin` true, saves, refreshes the tray and broadcasts, also WITHOUT touching the registry; with the setting off and no enabled entry for this exe the action is `'none'`; `'rewrite'` (an enabled entry at another exe, the rename upgrade) registers the current exe (`openAtLogin: true, enabled: true`) and deletes an old `electron.app.*` entry. The exe is `PORTABLE_EXECUTABLE_FILE || process.execPath`. Ticking the box calls `setLoginItemSettings({ openAtLogin: true, path, enabled: true })` (a direct user action turns the entry back on). The NSIS uninstaller (`build/installer.nsh`, customUnInstall, skipped on updates by `${isUpdated}`) deletes the value under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` and `...\Explorer\StartupApproved\Run`.
- Store build: `launchAtLogin` cannot be set (VALIDATE returns undefined while `process.windowsStore`, read at call time, on load too); its startup task is managed only in Windows Settings > Apps > Startup.
- No proxy, network service in process: unless updates are enabled (`wcUpdates`), main appends Chromium's `no-proxy-server` switch and `enable-features=NetworkServiceInProcess2` before ready (the page is a local file and links open in the browser; the app makes no network requests), so there are no WPAD lookups, no proxy resolver process and no network service process. Keep ONE `enable-features` switch (a second appendSwitch with the same name replaces the first): add features to its comma list. deep.js checks both switches and, on the native backdrop path without `WC_GPU=1`, that GPU compositing is `disabled_software`.
- Software compositing on the native backdrop path: when `NATIVE_FRAME` (acrylic or mica) and env `WC_GPU` is not '1', main calls `app.disableHardwareAcceleration()` at module scope, before ready. DWM draws the acrylic and the map is a 2D canvas, so the GPU process only cost memory and CPU (measured: 122.9 to 107.1 MB, commit 222 to 146 MB, CPU 1.92% to 1.24%). The transparent path (Windows 10, `WC_BACKDROP=none`) keeps hardware acceleration: without it that path measured 2.4x the CPU. `WC_GPU=1` turns the GPU back on (A/B runs, escape hatch). Expected processes with both switches: browser, gpu (software), renderer.
- Env `WC_USER_DATA`: if set, call app.setPath('userData', value) before anything reads settings. Tests use this. Because that happens before `requestSingleInstanceLock` (keyed on the userData folder), `npm test` and `npm run shots` run while the installed app is open; test/run.js has no process check. test/deep.js and test/shots.js exit at once (exit code 2, deep.txt says why) when WC_USER_DATA is missing, so a suite can never run against the real profile. test/run.js keeps the app's stderr in test/deep-stderr.log (shots: test/shots-stderr.log, both git-ignored as *.log) and prints its last 40 lines when no report was produced.
- Env `WC_LANG`: default language when no saved value.

## Motion system (v1.2)
Files: src/renderer/motion/tokens.css (shared tokens; component files read them and never redefine them), motion/_shared.js (window.WCMotion: reduced(), on(name, fn), ms(varName), css(varName, fallback); token reads are cached and the cache is cleared when prefers-reduced-motion changes, the only query tokens.css changes under), and one pair per component: motion/<component>.css + motion/<component>.js. Motion CSS loads after style.css; motion JS loads before app.js.
Rules: app.js changes state, text, classes and `hidden` synchronously (tests read them immediately). Motion modules ONLY listen to events and animate transform/opacity/filter (or use temporary clones/overlays). Never delay or alter textContent, classes, ids, data-zone, or hidden that app.js sets. Use Web Animations API (element.animate) or CSS transitions with the tokens. Every animation must respect WCMotion.reduced() / the token overrides.
Map and planner entrance (round 2, motion/ambient.js): opening either runs the same short entrance as other surfaces (opacity 0 to 1 and translateY(--rise) to none, --dur-3, --ease-emphasized, no fill); when both are closed the cards come back the same way unless the layout crossfade already runs on `#strip`. Nothing with reduced motion.
No motion timers of their own: motion/sky.js follows `data-epoch`, the card classes and `time-change` (the minute render rewrites `data-epoch`), without a minute timer. views/map.js: the sun and its glow glide only for converter jumps (a live minute step jumps: `placeSun(ss, geoChanged || !converting)`) and carry no `will-change`; map pills are nearly opaque (0.97) instead of using a backdrop blur.
Formatter cache (round 2, time.js): `WCTime.fmt` keeps at most 300 Intl.DateTimeFormat instances (LRU: a hit moves to the end, the oldest goes first; `WCTime._fmtSize()` for tests). `WCTime.offsetMinutesUncached(zone, date)` gives the same offset with a throwaway formatter; app.js searchZones uses it for an offset search ("+5", "UTC+5") in a per-minute table (`searchZones.offsets`, dropped on search blur), so one search no longer fills the cache.
Time motion (motion/time.js): time-change events are queued and handled in one microtask (every layout read first, then every overlay and animation). `.card .time .hm` has no opacity transition (the digit roll hides it and must bring it straight back). A converted `.hm` gets one crossfade (a single `opacity: 0.4` start keyframe, so it ends at the element's own opacity), none when that `.hm` changed less than 300 ms before (scrubbing shows plain digits). The one `.card` transition list is in motion/cards.css (background, color, transform, box-shadow, opacity, border-color; `.card:active` durations follow that order, transform 120 ms). The day-line dot and the planner now-line only animate `left` while converting (`.card.converted .arc-dot`, `.plan-now.converted`); the live minute step jumps. During continuous scrubbing (scrub steps less than 300 ms apart, app.js `markScrub` in flushScrub) `.app` has `.scrub-live`, which drops those `left` transitions so the dots and the line follow each step; it is removed 300 ms after the last step, so a single step still glides. The digit roll overlay (`.digit-fx`) gives a box and two animations (`.dfx-c` > span + `.dfx-old`) only to the characters that changed; unchanged runs are plain text nodes.
Events (dispatched on document as `wc:<name>`, detail object):
- boot {strip}: first render done.
- zones-before {from, to}: fired synchronously BEFORE the card DOM changes (add/remove/reorder). Record card rects here (FLIP).
- zones-after {from, to}: fired right AFTER the DOM changed. Added zones = in `to` not `from`; removed = in `from` not `to` (their cards are already gone; clone them in zones-before if you need an exit animation).
- time-change {card, from, to, converting}: a card's .hm text changed.
- convert {on}: converter entered (true) or left (false).
- invalid {input}: unparseable time typed.
- copied {onlyZone}: copy succeeded.
- menu {open, menu, anchor?}: card menu opened (after positioning) or is about to close.
- results {open, list}: search results popover became visible.
- panel {open, panel}: settings opening (after hidden=false) or closing (fired just before hidden=true).
- tip-dismiss {tip}: fired just before the tip is hidden.
- layout {layout}: layout class is about to change.
- pin {on, button}: pin toggled.

## Per-view window sizes (v1.4)
Each view comes back at the size the user last gave it. Owned by src/main.js (`geo.key`, `geo.overlay`, `applyView`).
- View key = the overlay if one is open (`'map'` or `'planner'`, mutually exclusive), else the layout (`strip` | `compact` | `vertical`). Main knows the planner from the `planner` setting and the map from `wc.setView`; a page reload drops a stale `'map'`.
- Manual resize (the `resized` handler `measure`; ignored while the settings panel is open, snapped, maximized, or in a size loop that began snapped) sets `baseSize` and `viewSizes[key]`.
- Switching key: `viewSizes[oldKey] = baseSize`, then the window gets `viewSizes[newKey]`, or the default: layouts use the sizes above; map = `{ width: max(cur.width, 1160), height: max(cur.height, 360) }`; planner = `{ width: cur.width, height: max(cur.height, min(520, 112 + 30 * zones.length)) }` (six cities: 292; the renderer sizes planner rows 24 to 40 px, 24 being the labels' target size, and past that the body scrolls with the .more-below fade) (`cur` = size of the view being left). The top-left stays put and the result is clamped into the work area.
- While the settings panel is open, or the window is snapped/maximized, the new size is only recorded (`baseSize`) and applied when the panel closes / the window leaves the snapped or maximized state (same as layout changes before).
- A layout change while the map or planner is open closes the overlay (planner saved false) and applies the new layout's size in one step.
- View key for overlays in the vertical layout is `mapVertical` / `plannerVertical`. Defaults: mapVertical = `{ width: cur.width, height: max(cur.height, 640) }`; plannerVertical = `{ width: cur.width, height: min(760, 250 + 57 * zones.length) }` (fitted to the rows and the hour scale; it used to be at least the vertical window's height, which left about 150 px empty under the scale with five cities. 57 per city: a 24 px name row, 3 px, 24 px cells and the 6 px gap. 250: the top bar while converting (128: a click on a cell converts, and at 300 wide Back to now and Copy wrap onto a third row), the planner's padding, a three-line head, the gap and the hour scale. Six cities: 592).
- `bounds` is saved as before (resting position + current `baseSize`). On launch the window uses `viewSizes[startKey]` (startKey = `'planner'` if `planner`, else the layout) when present, at the saved position.
- Tray "Reset position" resets the current view to its default size (and stores it) at the default position.
